# BilsenBol — персональный маршрут поступления

> **Демо:** ⚠ ЗАПОЛНИТЬ — ссылка на развёрнутый сайт
> **Кейс:** LOCUS Startup Hackathon 2026, кейс 02 «Персональный маршрут поступления» (`LOCUSCASE2`)

BilsenBol превращает профиль школьника в понятный маршрут поступления: куда
подаваться, почему именно туда и что сделать на этой неделе.

---

## 1. Задача

Поступление — это десятки решений: направление, страна, вуз, экзамены,
документы, сроки. Информация разрознена, а рекомендации слишком общие, поэтому
абитуриент не понимает, что подходит именно ему и какое действие выполнить
сейчас.

**Аудитория:** школьники 9–11 классов и выпускники из стран СНГ, которые
поступают на бакалавриат, в том числе за рубеж.

## 2. Решение

Один связный путь из семи этапов кейса:

| Этап кейса | Что видит пользователь в BilsenBol |
|---|---|
| 1. Вход | Лендинг с ценностью сервиса, кнопка «Начать» и три пресета «в один клик» |
| 2. Профиль | Анкета из 6 вопросов, по одному на экран: класс, средний балл, английский, семейный бюджет, интересы, регионы |
| 3. Диагностика | Экран «Разбор»: резюме профиля, образовательная цель, статус готовности, сильная сторона, главное узкое место, запас времени |
| 4. Рекомендации | Программы, прошедшие обязательные условия. У каждой — оценка совпадения, причины, компромисс, что может помешать и как усилить заявку |
| 5. Сравнение | Две выбранные программы лицом к лицу по 10 критериям, с отметкой лучшего значения в каждой строке |
| 6. Roadmap | План по сезонам (осень, зима, весна): экзамены, документы, письма, заявки, гранты, активности, виза |
| 7. Следующее действие | Карточка «Следующий шаг» с кнопкой «Выполнено», чекбоксы шагов и шкала готовности в процентах |

Как это закрывает обязательные требования кейса к UX/UI:

- **Где я и что дальше** — степпер из четырёх шагов виден на любой ширине экрана, в анкете есть счётчик «N / 6», на плане выделен следующий шаг.
- **Объяснения человеческим языком** — у каждой рекомендации есть причины, компромисс, возможная помеха и совет, а также разбивка оценки по факторам.
- **Единая графическая система** — все цвета заданы токенами в одном файле; иконки Lucide; общий компонент кнопок; единые карточки и состояния.
- **Мобильная версия** — проверена на ширине 360 и 390 px, без горизонтальной прокрутки.
- **Реакция на изменение профиля** — панель «Ваши условия» на экранах результата меняет бюджет, английский, интересы, регионы и балл. После каждой правки плашка «Что изменилось» показывает, что именно сдвинулось: число программ, статус, лидер подборки, позиции в рейтинге, шаги плана. Если правка ни на что не повлияла, она так и говорит.
- **Источники и демо-пометки** — каталог программ демонстрационный и помечен «Демо-данные» на каждой карточке, в сравнении и в шапке; советы плана помечены как общие ориентиры.

## 4. Архитектура

Модульный монолит: бизнес-правила отделены от интерфейса.

```text
src/
  app/                    маршруты: / (лендинг) и /journey (путь)
  domain/                 чистые функции без React:
    profile.ts              профиль, варианты ответов, пресеты, валидация
    matching.ts             жёсткие ограничения, скоринг, объяснения
    diagnosis.ts            статус, резюме, сильная сторона, узкое место
    roadmap.ts              план по сезонам и расчёт прогресса
    comparison.ts           строки сравнения двух программ
  data/programs.ts        демонстрационный каталог (вымышленные вузы)
  features/               экраны пути: profile, diagnosis, recommendations,
                          comparison, roadmap, progress, journey
  components/             общие компоненты: кнопки, фон, появление при прокрутке
  lib/                    утилиты: безопасный localStorage, склонения, анимация чисел
```

**Поток данных.** Единственный источник состояния — профиль. Разбор, подборка
и план каждый раз заново вычисляются из профиля, а не правятся по месту,
поэтому любая правка сразу отражается на всех экранах.

**Логика рекомендаций** — прозрачные правила, без «чёрного ящика».

1. **Жёсткие ограничения** отсекают программу целиком: регион вне выбранных; стоимость выше бюджета (при бюджете «$0» нужен полный грант); минимальный балл выше вашего; обязательный языковой сертификат без подготовительного года, если сертификата нет.
2. **Мягкие факторы** складываются в оценку совпадения от 0 до 100:

   | Фактор | Баллы |
   |---|---|
   | Проходит обязательные требования | 6 |
   | Совпадает с выбранным направлением | 34 |
   | Полностью покрывается грантом / запас бюджета | 6–18 |
   | Язык: сертификат есть / не требуется / есть Foundation | 14 / 12 / 9 |
   | Средний балл выше минимального | 0–14 |
   | Выбранный регион | 8 |
   | Поступление сразу после 11 класса | 6 |

   Оценка показывает, **насколько программа совпадает с профилем**. Это не вероятность поступления: сервис не обещает шансов и не гарантирует поступление.

3. **Объяснение** каждой рекомендации собирается из тех же факторов: почему подходит, какой компромисс, что может помешать, как усилить заявку.

**Сохранение.** Профиль, текущий шаг и отмеченные шаги плана пишутся в
`localStorage` (ключ `bilsenbol.journey`, версия схемы 1). При чтении данные
проверяются поле за полем; повреждённые данные или данные другой версии
отбрасываются целиком. Если хранилище недоступно, путь работает в памяти.
Кнопка «Начать заново» стирает прогресс после подтверждения.

## 5. Запуск

```bash
npm install
npm run dev
```

Откройте <http://localhost:3000>.

Чтобы открыть dev-сервер с телефона в той же сети, используйте адрес из вывода
`next dev` (например, `http://192.168.x.y:3000`). Адреса `192.168.*.*`
разрешены в `next.config.ts`.

Сборка и проверки:

```bash
npm run typecheck
npm run lint
npm run build
npm start
```

Регистрация и вход не нужны, тестовый логин не требуется.

## 6. Тестовый сценарий

Повторяет проверочный сценарий жюри из кейса.

1. **Полный путь.** На главной нажмите «Начать», ответьте на 6 вопросов и нажмите «Построить мой маршрут».
2. **Разбор.** Проверьте резюме профиля, цель, статус готовности и три вывода.
3. **Рекомендации.** Нажмите «Дальше: Подбор». У программы раскройте «Подробнее»: причины, компромисс, как усилить заявку, разбивка оценки по факторам.
4. **Сравнение.** Нажмите «Сравнить» на двух карточках, затем «Сравнить» на нижней панели.
5. **Реакция на изменения.** Нажмите «Ваши условия → Изменить» и поменяйте бюджет, интерес, регион или экзамен. Плашка «Что изменилось» покажет сдвиги. Например, для IT-пресета бюджет «До $3 000» даёт «Программ: 6 → 5».
6. **Следующий шаг и прогресс.** На шаге «План» нажмите «Выполнено»: шкала готовности вырастет. Обновите страницу — прогресс сохранится.
7. **Быстрый старт.** На главной выберите пресет: «Отличник, нужен грант», «IT, средний бюджет» или «Без IELTS, нужен Foundation».
8. **Пустое состояние.** В IT-пресете откройте «Ваши условия», выберите бюджет «$0 — только грант» и оставьте из регионов только «США» (сначала отметьте США, затем снимите остальные). Появится «Ничего не подошло» с причинами отсева и кнопкой, которая смягчает условие, отсеявшее больше всего программ.
9. **Мобильная версия.** Пройдите путь на ширине 360–390 px.

## 9. AI и API

- **В продукте:** рекомендации, разбор и план строятся на прозрачных правилах (rule-based логика), как разрешает кейс. Языковая модель в текущей версии не вызывается, внешние API не используются. Решение осознанное: жёсткие ограничения должны быть детерминированными и проверяемыми, а модель не должна выдумывать требования и сроки.
- **При разработке** команда использовала ИИ-ассистентов для кода. Правила их работы описаны в `AGENTS.md`, журнал задач ведётся в `AGENTS_CHANGELOG.md`.

## 10. Готовые компоненты

- **Lucide** (`lucide-react`, лицензия ISC) — иконки.
- **Next.js** — встроенные `next/image` (оптимизация фото) и `next/link`.

UI-кит не использовался: кнопки, карточки, анкета, степпер, сравнение, таймлайн
и фон написаны в проекте.

## 11. Ограничения

- Каталог — демо-данные вымышленных вузов, поэтому рекомендации демонстрируют работу правил, а не реальные маршруты.
- Из экзаменов учитывается только английский: IELTS, TOEFL, Duolingo или школьный уровень. Национальные экзамены (ЕНТ, ЕГЭ, SAT) не моделируются.
- Регионы, а не отдельные страны.
- Прогресс хранится в браузере: нет аккаунтов и синхронизации между устройствами.
- Сравниваются ровно две программы.
- Реальных дедлайнов нет, только сезоны. Окна подачи в каталоге — демо-данные.
- Автотестов в репозитории пока нет (см. раздел 12).

## 12. Техническая справка

| Пункт | Значение |
|---|---|
| Модели | Языковые модели не используются |
| Внешние API и сервисы | Нет; фотографии хранятся локально |
| Библиотеки | next, react, react-dom, lucide-react; для разработки — typescript, eslint, eslint-config-next |
| Данные | `src/data/programs.ts` — демо-каталог; пользовательские данные остаются в браузере (`localStorage`) и никуда не отправляются |

**Методы проверки.**

- `npm run typecheck`, `npm run lint`, `npm run build` — завершаются без ошибок.
- Доменная логика проверялась отдельными прогонами: у каждого пресета ≥ 3 программ; жёсткие ограничения никогда не нарушаются; невозможный профиль даёт 0 программ с полным разбором причин; смена бюджета, языка, интереса и региона меняет подборку, разбор или план; расчёт прогресса.
- Интерфейс проверялся в headless Chrome с эмуляцией касаний на 360 и 390 px: нажатие каждого основного элемента, сохранение после перезагрузки, повреждённое и недоступное хранилище, плашка «Что изменилось», отсутствие горизонтальной прокрутки.
- Эти прогоны выполнялись во время разработки и **не входят в репозиторий** — перенести их в Vitest и Playwright запланировано следующим шагом.
